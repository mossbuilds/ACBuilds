# PetSpells
Source only, not compiled or deployed. OFF by default. Player-owned CombatPets (weenie ids in MinionWcids, default 900021240) cast an EXISTING spell periodically: SpellOnTarget at the pet's AttackTarget (debuff), SpellOnOwner on the owner (heal/buff). Admin /petspells shows status ("petspells" is not a built-in name).
Overlap: RaiseSkeleton creates minions, MinionOrders steers targeting (attack/hold), MinionCleanup removes strays. None of them makes a minion cast; that is what is new here. Reuses the same PetOwner / MinionWcids selection.
How a minion casts: 1 s timer sweeps loaded landblocks (queue only); per pet, cooldown CastIntervalSeconds (min 5), owner online, same landblock, within MaxRange, cap MaxCastsPerSecondPerOwner; then an ActionChain on the pet calls WorldObject.TryCastSpell(new Spell(id), target, tryResist) on the pet itself (verified: TryCastSpell is on WorldObject, ACE.Server.WorldObjects, so any Creature can call it). Bypasses ACE's monster spell code and the advanced_combat_pets server property, so no spell book on the weenie is needed.
Settings.json: Enabled, MinionWcids, SpellOnTarget, SpellOnOwner, Debuff, Buff, CastIntervalSeconds, MaxRange, ManaFree (true), ManaCost, MaxCastsPerSecondPerOwner.
Unverified: not compiled; that TryCastSpell works from a non-Player caster for every spell type (buff/heal on a Player target should send the player its messages); pet AttackTarget is set only while the stock AI has a target; no cast animation plays. Fizzle/resist follow tryResist.
