# ACE mod ideas (ACBuilds)

Verification: Player_Death.cs (OnDeath, Die, InflictVitaePenalty, CalculateDeathItems, GetNumItemsDropped, HandlePKDeathBroadcast, ThreadSafeTeleportOnDeath) and Player_Xp.cs (EarnXP, GrantXP, GrantLevelProportionalXp, SpendXP, RefundXP) verified via raw GitHub. Mods folder holds IHarmonyMod, ModManager, ModContainer, ModCommands, ModHelpers, ModMetadata (verified listing; BasicMod/BasicPatch API taken from local PatchClass.cs). Everything else marked UNVERIFIED must be checked in source before coding. WebSearch of forums/other mods was not done. Rules: no speed/velocity mods (client-side); no mods that add many world objects (Quest memory).

Common style: [HarmonyPatch] class : BasicPatch<Settings>, [CommandHandler(name, AccessLevel, CommandHandlerFlag.RequiresWorld, paramCount, desc, usage)], PlayerManager.GetOnlinePlayer, ActionChain(player, ...).EnqueueChain(), GameMessageSystemChat.

1. XpBoost (feas 5) - Configurable XP multiplier (per-level tiers, weekend event). Postfix/prefix on Player.EarnXP(long, XpType, ShareType) scaling amount by Settings.Multiplier. Cmds: /xpboost [x] (Admin). Settings: Multiplier, MaxLevel, XpTypes affected. Risks: double counting via GrantXP (which calls EarnXP? check); prefix arg change with ref long amount.
2. GentleDeath (feas 5) - Softer death: fewer dropped items, reduced vitae. Postfix on Player.GetNumItemsDropped(Corpse) (return __result, cap), prefix on InflictVitaePenalty(int) to scale amount. Settings: MaxItemsDropped, VitaeAmount, ProtectPlayerCorpseOnly. Risks: balance; PK paths.
3. WhereIsEveryone / PlayerFinder (feas 5) - Admin /who with location, level, landblock; /gotoplayer via player.Teleport(target.Location), /bring. Uses PlayerManager.GetAllOnline (UNVERIFIED name; existing code uses GetOnlinePlayer). Settings: none. Risks: minimal.
4. AnnounceEvents (feas 4) - Scheduled server broadcasts and timed XP/loot events (System.Threading.Timer + PlayerManager.BroadcastToAll (UNVERIFIED)). Cmds: /event start|stop name. Settings: schedule list. Risks: timer threading; wrap in ActionChain.
5. HomeStone / SetHome (feas 4) - /sethome saves player.Location to a settings JSON/DB property; /home teleports with cooldown, blocked in combat (player.LastPkAttackTimestamp / IsPKType UNVERIFIED). Settings: CooldownSeconds, AllowIndoors. Risks: teleport into invalid cell; use Teleport(Position).
6. SafeTutorZone / PkGuard (feas 3) - Disable PvP damage in configured landblocks by prefixing Player.TakeDamage / Creature damage path (UNVERIFIED exact method; inspect Player_Combat.cs). Settings: landblock list. Risks: skipping original with prefix returning false; hard to test.
7. AutoLoot / PickupRadius (feas 3) - /autoloot: on corpse open (Corpse.Open / Container.Open UNVERIFIED) move items to pack via player.TryCreateInInventoryWithNetworking. Settings: filters (pyreals, trade notes). Risks: pack full, races.
8. Buffbot Command (feas 4) - /buffme casts standard buff list via player.CreateSingleSpell / EnchantmentManager (UNVERIFIED); cooldown, free or cost. Settings: spell ids, cost. Risks: spell id correctness, balance.
9. Leaderboard (feas 4) - /top shows level/XP/kills from PlayerManager.GetAllPlayers (UNVERIFIED) plus kill tally via postfix on Player.OnDeath/Creature.Die. Settings: size. Risks: offline players load cost, cache.
10. AdminAudit (feas 5) - Log every admin command and spawn to a file. Patch CommandManager.ParseCommand (UNVERIFIED) prefix, or use own [CommandHandler]s. Settings: log path. Risks: none.
11. DeathReport (feas 5) - Postfix Player.OnDeath: broadcast fun message, log location, optional /lastdeath teleports player to death location (store Position from Location at Die). Settings: broadcast on/off. Risks: spam.
12. RestartWarn / Maintenance (feas 4) - /restartin N broadcasts countdowns then calls shutdown (ServerManager.Shutdown UNVERIFIED) and blocks logins in the window. Settings: warn intervals. Risks: shutdown API must be checked.

Ranking is by usefulness times feasibility; 1-3 and 10-11 are the best first builds.

13. MilestoneRewards (feas 4) - Grants skill credits (and a chat line) at configured levels/first-time milestones, a common small-server "no reason to reroll" QoL. Hooks: Postfix on Player.CheckForLevelup (ACE.Server.WorldObjects; UNVERIFIED name, inspect Player_Xp.cs) then player.AddSkillCredits(int) (verified in Player_Skills.cs, ACE.Server.WorldObjects). Notify via GameMessageSystemChat (ACE.Server.Network.GameMessages.Messages). Cmd: /milestones (player) shows next reward. Settings: LevelToCredits map, OneTimeOnly. Risks: double-grant on relog (track in mod's own JSON keyed by character id, not the DB); balance. Source: https://github.com/aquafir/ACE.BaseMod (patch-template ecosystem, credits/XP tweaks are typical samples).

14. IdleKick (feas 4) - Warns then logs off players idle beyond N minutes to free slots and stop AFK-camping. Hooks: Postfix on Player.Player_Tick(double) or Heartbeat(double) (both verified in Player_Tick.cs, ACE.Server.WorldObjects); compare to last-input time kept in a per-player dictionary updated in Postfix on Player.OnMoveToState(MoveToState) (verified); kick via Session.LogOffPlayer(bool) (used in Player_Tick.cs; class ACE.Server.Network.Session). Cmd: /idle (Admin) list idle times. Settings: WarnMinutes, KickMinutes, ExemptAdmins. Risks: chat/casting-only players look idle (also hook chat); Tick postfix cost, so throttle to once per few seconds. Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/WorldObjects/Player_Tick.cs (no idle logic exists, only teleport timeout).

15. TimedMute (feas 5) - Admin /mute name minutes [reason] with auto-unmute and a persisted list, wrapping stock gag. Hooks: PlayerManager.GagPlayer(Player issuer, string playerName) and UnGagPlayer(Player, string) (verified, ACE.Server.Managers); Timer/ActionChain to un-gag; Postfix Player.OnEnterWorld/PlayerEnterWorld() (verified, Player_Networking.cs) to re-apply. Cmds: /mute, /unmute, /mutes (AccessLevel.Sentinel, CommandHandlerFlag.RequiresWorld). Settings: DefaultMinutes, MaxMinutes. Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/Managers/PlayerManager.cs

17. PkNight (feas 4) - Scheduled PK windows (e.g. Friday 20:00-22:00) for servers that are PvE otherwise: announces, flips PK status for all online players, flips back, with warnings and an /pknight now|off admin override. 18. LoginGreeter (feas 5) - Per-login MOTD plus "who is online / what's new / next event" whisper, with a first-login welcome pack of tips. Hooks: Postfix Player.PlayerEnterWorld() (verified, ACE.Server.WorldObjects); PlayerManager.GetOnlineCount() and GetAllOnline() (verified); GameMessageSystemChat. Cmd: /motd (player), /setmotd text (Admin). Settings: MotdLines, ShowOnlineCount, FirstLoginTip. Risks: chat sent before client ready (delay 2-3 s via ActionChain); keep it small, no world objects. Cmd: /pulse [top] (AccessLevel.Sentinel, CommandHandlerFlag.RequiresWorld). Settings: TopN. Risks: enumerating a snapshot is safe; do not touch landblock internals from the command thread beyond reading counts. Source: https://github.com/ACEmulator/ACE/issues (fetched) and https://github.com/ACEmulator/ACE/wiki/ACE-Hosting.

20. HotspotAlert (feas 4) - Quest-friendly crowd guard: a throttled timer scans loaded landblocks and whispers online admins when one exceeds a creature/player threshold (the cause of lag and headset memory pressure), once per cooldown per landblock. Never spawns or deletes anything. Hooks: LandblockManager.GetLoadedLandblocks() (verified); Landblock counts (UNVERIFIED, ACE.Server.Entity); PlayerManager.GetAllOnline() (verified earlier) filtered by Session.AccessLevel (UNVERIFIED); GameMessageSystemChat (ACE.Server.Network.GameMessages.Messages); timer wrapped in ActionChain. Cmd: /hotspots (Sentinel). Settings: CreatureThreshold, PlayerThreshold, ScanSeconds, AlertCooldownMinutes. Risks: scan cost, so keep to every 30+ s; false alarms at events. Source: https://github.com/ACEmulator/ACE/wiki/ACE-Hosting (fetched, load scaling and thread settings).

21. StatCard (feas 4) - Player command that prints a readable one-screen character summary (level, XP to next level, unassigned credits, luminance if present, attribute and vital totals, top skills, deaths) in plain chat lines, from the ACE Discussions "view_readable_stats" idea (RandomTurtle, Jan 2026). Read-only, no world objects, useful for VR players who cannot easily open panes. Hooks: own [CommandHandler] only; reads Player members in ACE.Server.WorldObjects (Level, TotalExperience, AvailableSkillCredits, Strength/Endurance etc. property names UNVERIFIED, read Player_Skills.cs and Creature_Attributes.cs); Skill enum = ACE.Entity.Enum; output via GameMessageSystemChat. Cmd: /statcard [top] (AccessLevel.Player). Settings: TopSkills, ShowDeaths. Risks: property names, avoid Player.GetXpToNextLevel-style guesses. Source: https://github.com/ACEmulator/ACE/discussions (fetched).

22. BugNote (feas 5) - Lets players leave a short note that goes to a mod-owned log file and a whisper to online admins, so a small private server hears about broken quests, stuck spots and exploits without Discord. Distinct from stock reportbug (which exists in PlayerCommands.cs, so this must not reuse that name; check what reportbug does first and drop the idea if it already logs). Hooks: own [CommandHandler]; PlayerManager.GetAllOnline() (verified earlier); records Player.Location (ACE.Entity.Position, namespace UNVERIFIED) and name; file write only in the mod folder. Cmds: /bugnote text (Player, 1 param, rate limited), /bugnotes [n] (Sentinel) reads the last n. Settings: CooldownSeconds, MaxLength, LogPath. Risks: spam (cooldown), no personal data beyond character name. Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/Command/Handlers/PlayerCommands.cs (fetched, shows reportbug).

23. LoginShield (feas 3) - Short damage immunity after entering the world, addressing ACE issue #950 "Improve Player EnterWorld Process" (players arriving into aggro, invisible or unloaded surroundings). Immunity lasts N seconds or until the player attacks or moves far. Hooks: Player.PlayerEnterWorld() and Player.LoginTimestamp (both verified from Player_Networking.cs, ACE.Server.WorldObjects; LoginTimestamp is set to Time.GetUnixTime() there); prefix on Player.TakeDamage (same method PkGuard patches; take its exact signature from the local PkGuard PatchClass.cs, still UNVERIFIED against master). Settings: ShieldSeconds, BreakOnAttack. Risks: exploit as a safe-fight buffer (break on outgoing attack), PvP interaction with PkGuard and PkNight (patch order). Source: https://github.com/ACEmulator/ACE/issues (fetched, #950).

Never modifies anything; uses ACE's own in-memory PropertyManager, not ace_shard. Hooks: PropertyManager.GetBool/GetLong/GetDouble/GetString(string key, fallback) and ListProperties() (all verified, ACE.Server.Managers; stock 'config' is a player command, so name differs). Cmd: /peekprop key (Admin; command name UNVERIFIED for clashes, grep first). Settings: AllowedPrefixes (restrict to safe keys, hide anything credential-like). Risks: some property values could be sensitive, hence the allowlist; Property<T> value member name UNVERIFIED (read Property.cs). Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/Managers/PropertyManager.cs (fetched).

25. MinionCleanup (feas 4) - Fixes what RaiseSkeleton needs: stock ACE tracks ONE pet per player (Player.CurrentActivePet) and destroys it in Player.LogOut_Inner(bool clientSessionTerminatedAbruptly = false); Pet.SlowTick() destroys a pet when its owner is beyond MaxDistance (192.0), so minions vanish on long teleports, and nothing handles owner death. This mod keeps a mod-side registry owner guid -> minion guids and (a) on a Player.LogOut_Inner prefix destroys all registered minions, (b) on Player.Die (protected override; patch via AccessTools) destroys or dismisses them, (c) on Player.Teleport(Position _newPosition, bool fromPortal = false) Postfix re-places them via ActionChain 3 s later at the owner's new Location (or destroys them, setting), (d) a Heartbeat sweep drops registry entries whose object is gone and enforces a hard ControlLimit. Classes: Player.LogOut_Inner, Player.Die, Player.Teleport, Pet.P_PetOwner, Pet.SlowTick, CombatPet.Init(Player, PetDevice) (all ACE.Server.WorldObjects, verified); WorldObject.Destroy(); ActionChain (ACE.Server.Entity.Actions, UNVERIFIED). Offers a static Register/Unregister/Count API to RaiseSkeleton. Cmd: /minionclean (Admin) shows registry counts. Settings: DestroyOnLogout, DestroyOnDeath, FollowThroughTeleport, ControlLimit, SweepSeconds. Risks: re-place must use RaiseSkeleton's spawn path (never clone); double destroy (check IsDestroyed); wrap Destroy in ActionChain. Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/WorldObjects/Pet.cs

26. MinionOrders (feas 3) - Squad orders: /order attack|hold|follow|recall. Stock CombatPet picks its own targets: FindNextTarget() (public override bool) chooses from GetNearbyMonsters(), HandleFindTarget() validates; Pet.StartFollow() walks to the owner beyond MinDistance 2.0. Prefix on CombatPet.FindNextTarget returns false while a minion is on Hold/Follow so it never engages; Attack sets the pet's AttackTarget to the owner's selection (owner selection member UNVERIFIED) then lets original logic run; Recall calls Pet.StartFollow() and Sleep(). Legality via Creature.CanDamage(Creature) (verified, Creature_Combat.cs) so orders cannot make a pet hit players or NPCs. Cmds: /order <attack|hold|follow|recall> [all|name] (Player, RequiresWorld); state in a ConditionalWeakTable<CombatPet, OrderState>, no DB. Settings: DefaultOrder, OrderCooldownMs, AllowAttackPlayers=false. Risks: prefix must not starve HandleFindTarget on Hold; several pets per owner is not native (pairs with MinionCleanup). Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/WorldObjects/CombatPet.cs

27. PathChoice (feas 4) - /path necromancer|rogue|fighter|mage with a respec cooldown: the Phase 0 gate. Stores the path as a quest stamp through QuestManager (ACE.Server.Managers; Stamp, HasQuest, Erase, GetCurrentSolves verified; the Player accessor name is UNVERIFIED because Player_Quests.cs 404ed). Grants a title with Player.AddTitle(CharacterTitle title, bool setAsDisplayTitle = false) or AddTitle(uint, bool) (verified, Player_Character.cs; CharacterTitle in ACE.Entity.Enum, existing ids only). Exposes static PathChoice.GetPath(Player) so RaiseSkeleton, CorpseBurst and AmbushStrike refuse wrong paths, and the quest-name convention lets NPC emotes gate content with no code. Cmds: /path, /path <name> confirm (Player); /pathset <player> <name> (Admin). Settings: Paths, RespecCooldownHours, TitleIds. Risks: stamps persist through ACE itself (never write SQL); enum id typos; block respec in combat. Source: https://raw.githubusercontent.com/ACEmulator/ACE/master/Source/ACE.Server/Managers/QuestManager.cs
